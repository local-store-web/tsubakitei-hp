# ツバキ亭：ランチのセクション追加／ディナーの小分類

## 対象と完了条件

対象は「ツバキ亭メニュー」（`tsubakitei-menus`）だけ。デリ・3号店・ドメイン・検索設定は変更しません。

**GitHubの改修だけでは、microCMS管理画面の選択肢やフィールドは増えません。** 以下の設定をmicroCMSで行い、商品を公開してHP上で確認した時点で運用開始です。本書は設定手順であり、設定済みという報告ではありません。

サイト側は「セクション名」で大見出しを生成します。今回、Dinnerに任意の「小分類」を追加できるようにしました。小分類が空欄の商品は今までどおり表示されます。既存商品の品名・価格・写真・公開状態・予備JSONは変更しません。

## 制作担当（麻生）が行う設定

microCMS管理画面：https://tsubakitei-hp.microcms.io/

1. 「ツバキ亭メニュー」→「API設定」→「APIスキーマ」を開き、現状をエクスポートして保管します。
2. **既存の「セクション名」フィールド**の選択肢に「トッピングメニュー」「サイドメニュー」を追加します。「アルコール」「ソフトドリンク」は既存選択肢にあればそのまま使用します。
3. 既存のフィールドID、種類、既存選択肢を変更・削除しません。過去の移行によりIDが `sectionName`、`sectionNameSingle`、`sectionNameSelect` のいずれかの場合も、新しく同名フィールドを作り直さず、実際に使用中の欄を編集します。
4. 以下の任意フィールドを1つ追加します。同じIDが既にある場合は重複作成せず、種類と用途を確認してください。

| 設定項目 | 設定値 |
|---|---|
| 表示名 | 小分類 |
| フィールドID | `subsectionName` |
| 種類 | セレクト |
| 複数選択 | OFF（単一選択） |
| 必須 | OFF |
| 初期値 | 未選択（「なし」という選択肢は作らない） |
| 初期選択肢 | ウイスキー各種／ブランデー／日本酒／リキュール |

初期選択肢は店舗からの依頼文・参考メニューにある見出しを使用しています。他の小分類が必要になったら、制作側で選択肢を追加します。新しいAPIや新しいCMS、料金プランの変更は不要です。

5. 詳細設定を閉じてAPIスキーマの「変更する」を押します。既存コンテンツ・APIの削除や、全件再インポートは行いません。
6. 入稿画面で「セクション名」の新しい選択肢と「小分類」が選べることを確認します。

**公開サイトに配置しているAPIキーはGET専用のままにします。CMS設定変更のために書き込み権限を付けないでください。**

## 店舗側が選ぶ組み合わせ

設定完了の連絡後は、店舗側は登録済みの選択肢を選ぶだけです。

| 表示したい場所 | メニュー区分 | セクション名（大分類） | 小分類 |
|---|---|---|---|
| ランチのトッピング | Lunch | トッピングメニュー | 未選択 |
| ランチのサイド | Lunch | サイドメニュー | 未選択 |
| ディナーのウイスキー | Dinner | アルコール | ウイスキー各種 |
| ディナーのブランデー | Dinner | アルコール | ブランデー |
| ディナーの日本酒 | Dinner | アルコール | 日本酒 |
| ディナーのリキュール | Dinner | アルコール | リキュール |
| ディナーのその他アルコール | Dinner | アルコール | 未選択 |
| ディナーのソフトドリンク | Dinner | ソフトドリンク | 未選択 |

HPでは「アルコール」という大見出しの下に「ウイスキー各種」などの小見出し、その下に商品が並びます。商品がなければ小見出しだけを出すことはありません。小分類はDinnerでのみ有効です。LunchとCourseでは使いません。

品名・金額表示・写真・表示するの操作は既存マニュアルのままです。価格は店が確認した最新の表示額を入力し、参考写真から一括で置き換えません。

## 既存商品の移動と重複防止

- 既存の商品がある場合、新しく複製せず、その商品の「セクション名」「小分類」を変更して公開します。
- リポジトリの予備JSONには、Dinnerの「ドリンク」セクション内に「アルコール」「リキュール」という品名の一覧説明カードがあります。**これらは小分類そのものではありません。** 現在のmicroCMSのデータは管理画面で確認してください。
- 旧一覧説明カードを個別の商品へ置き換える場合は、必要な内容を漏れなく移してHPで確認した後に、旧カードの「表示する」をOFFにして公開します。一覧説明だけを先に消してはいけません。
- 既存の「単品」から新しい「サイドメニュー」へ移す場合も、商品を複製・削除しません。
- 空の見出しを出すための仮商品、`￥...` のままの商品は公開しません。

## 並び順

従来の `sortOrder`（並び順）の小さい数字から処理します。セクションと小分類は、その分類で最初に現れる商品の順で並び、同じ小分類は一か所にまとまります。小分類未選択の商品同士も一つのまとまりになります。

「主菜→トッピング→サイド」にしたい場合は、各分類の最初の商品がその順になるよう、現在の数値を制作担当が確認して割り当てます。実データ未確認のまま、全商品を10・20・30等に振り直さないでください。小分類内の商品順も `sortOrder` に従います。

## 商品数が増えた場合

サイトは100件ずつ、APIの `totalCount` に達するまで順に取得します。101件目以降が無視される問題を解消しています。非表示の商品も取得件数に含まれますが、HPには表示しません。途中の取得が失敗した場合は、不完全なCMSデータを混ぜず、従来の予備データ経路に切り替えます。API・契約プランの制限をなくす変更ではありません。

## 公開前チェック

- ツバキ亭メニューの対象商品であること。
- Lunchの追加2セクションに、意図した商品だけが出ること。
- Dinnerの大分類・小分類と商品が一致すること。
- 旧一覧説明と新商品が重複していないこと。
- 「表示する：OFF」の商品が出ないこと。
- 長い商品名・S/M価格がスマホで潰れないこと。
- Course・デリの表示を意図せず変更していないこと。
- 変更内容を公開してから、確認ページを再読み込みすること。

確認ページ：https://local-store-web.github.io/tsubakitei-hp/menu/
